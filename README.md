# PM

PMO Lite 独立项目管理系统，V1.0.4 规格的开发仓库。当前可在隔离开发环境演示人工台账、部分业务流程和 MCP 工具，**尚未完成阶段验收，不可上线**。当前覆盖范围和续接顺序见[进度与续接索引](docs/progress/handoff.md)，逐项证据见[追踪矩阵](docs/acceptance/traceability.csv)。

## 本地复验（Windows PowerShell）

需要 Python 3.12、uv 及运行中的 Docker Engine。首次初始化会在 `.local` 下生成本机开发数据库随机口令，不设默认管理员，也不提交凭据。Compose 只启动隔离的数据库。

```powershell
.\scripts\dev.ps1 setup
npm.cmd --prefix web ci
.\scripts\dev.ps1 check
.\scripts\dev.ps1 test
.\scripts\dev.ps1 browser
.\scripts\dev.ps1 bootstrap
.\scripts\dev.ps1 api
```

OpenAPI：`http://127.0.0.1:8000/openapi.json`。API 只在回环地址开发。测试通过随机 PostgreSQL schema 创建合成数据，启动单独的 HTTP 和 MCP 进程；不要将测试 URL 指向生产库。API 不会返回未授权的项目。

在第二个 PowerShell 中执行 `.\scripts\dev.ps1 web`，访问 `http://127.0.0.1:5173`。首次使用空库 bootstrap 交互输入组织、账号、姓名和口令，需至少 14 字符，不回显。不能在已初始化库重复运行。系统管理员不自动获得任何项目审批角色。Web 可登录、维护项目资料、查看风险与成本，并进行关口预检。退出会撤销数据库会话。构建命令 `npm.cmd --prefix web run build`。浏览器测试在 Windows 默认使用已安装的 Microsoft Edge，不需要生产口令或模型密钥。

点击项目名称可维护里程碑（最多八个）及需求草稿。项目进入冻结阶段后，草稿编辑权限不会代替正式变更审批。

项目资料的「联系台账」按项目登记客户、合作方及内部联系人，并记录影响力和期望。登记不会创建账号、绑定客户身份或授予签收权。人工项目成员可分页查看联系详情，Agent 仅在授权项目详情中获得最多 100 条摘要。

在项目资料的「立项卡」页签填写并保存材料；允许草稿信息不完整，保存不表示送审或批准。人工可读完整材料，Agent 通过项目详情只读契约允许的摘要。

项目资料的「关口送审」可查看预检和评审记录。已指派的独立人工评审人可逐维引用材料打分；发起方可申请一次评分复议或在材料过期时撤回。隔离测试可通过有权 Reviewer 原子裁决并推进立项与落地；真实终裁仍受未签政策阻断。结项预检和当前边界见[续接索引](docs/progress/handoff.md)。

「日报周报」中的已提交报告可展开「Fact 证据与澄清」。候选引用该版本的原话，核验时会重读来源；高可信还需从本报告已独立核验的附件选取客观证据。冲突进入 PM 澄清任务，完成后仍保留原话及前后核验记录。模型关闭时可人工完成，候选与争议不进入正式三线。见 [Fact 出处和权限](docs/adr/0012-fact-source-and-clarification.md)。

同一工作区的「报告分析」仅对报告作者与本项目 PM 开放。模型默认关闭，此时可转人工任务，也可直接手工提报。显式启用后，由 `python -m pmo.report_analysis_worker --watch` 领取作业；本地已迁移的隔离库可用 `scripts/dev.ps1 analysis` 处理一批。建议与 Fact 分开保存，须由人工选用、保存、核验。开关、网关配置与隐私边界见[数据库运行账号隔离](docs/ops/database-roles.md)和 [ADR 0013](docs/adr/0013-report-analysis-jobs.md)。

「日报周报」的「生成周报初稿」仅向本项目现任 PM 开放，不需要模型。可按周预填四区块、保留生成依据并编辑，提交后仍须 PM 确认发布。核验人天与申报人天分开显示；相关来源发生变化时保留旧稿并要求重新生成。见 [ADR 0015](docs/adr/0015-weekly-report-basis.md)。

项目资料的「项目助理」提供立项评审、过程管家、结项回顾和台账问答。立项仅引用正式评分摘要和有权限的已确认教训；过程管家限现任 PM，展示当前来源、报告候选和周报预览；结项复用人工门槛和四问；问答按受控主题查询，证据不足时明确未知。助理只读，不创建 Fact、发布报告、提交审批或推进阶段。关闭模型仍可使用。

「需求例外」在交付与结项评审阶段显示具体缺口、有效回执和核验原件。隔离测试中，独立客户代表可签署并撤销列明需求版本、偏差和有效期的书面接受；PDF 通过「证据附件」上传并由另一名有权评审人核验。此回执只能作为条件结项的需求依据，对账、双口径成本和风险仍独立复核。真实政策 DEC-09 未签核。

展开「需求」的单条记录可打开「客户争议」。合成环境中，已绑定的独立客户代表可就当前基线提出正式争议并明确撤回。仍有效的争议使质量线标红、阻止结项，并使此前送审的相关材料快照失效；历史仍可见。见 [ADR 0017](docs/adr/0017-customer-requirement-disputes.md)。

工作台的「人员任命」支持发起人选择草稿并按同组织人员 ID 提名 PM 或 Sponsor。提名不会授予项目权限；有独立组织授权的人员在「待我发出的邀请」处理，被提名人从「我的邀请」接受或拒绝。实际业务任命权仍需签核，不为初始管理员自动开通。

项目资料的「项目成员」只展示有效成员角色。发起人自动登记为本草稿的 initiator，不能因此成为 PM 或 Sponsor，也不获得跨阶段的代理授权。

具有组织系统管理角色的人工账号能打开「审计记录」，按请求编号、结果查询本组织事件。HTTP 响应的 `X-Request-ID` 可用于核对记录；错误响应不回显提交的请求体。

「组织账号」可查看同组织人员和账号、一次性交付开户码、撤销未用邀请并启停普通账号。收件人在登录页「接受组织邀请」自行设置密码；职务提示不授予项目或组织权限。停用即撤销会话与委托令牌，重新启用后需要重新登录或签发。见 [ADR 0014](docs/adr/0014-organization-account-lifecycle.md)。

MCP stdio 命令：安装后使用环境中的 `pmo-mcp`（Windows 为 `.venv/Scripts/pmo-mcp.exe`），不要求以仓库为工作目录。从源码运行仍可在仓库根目录使用 `.venv/Scripts/python.exe -m pmo.mcp_server`。通过 `PMO_API_URL` 配置如 `http://127.0.0.1:8000/api/v1`；非回环应使用 HTTPS。不设置地址时回退到回环地址和 `PMO_API_PORT`（默认 8000）。可用 `uv build --out-dir .local/mcp-dist` 构建本机适配器 wheel；它不是整套系统的部署包。真实目标 Host 证据见 [M3](docs/progress/M3-report.md)。

具有 delegator 资格的人工用户通过「我的 Agent 令牌」选择项目、动作和最长 24 小时有效期。一次性交付的密钥只通过受保护的进程环境变量 `PMO_AGENT_TOKEN` 注入，不写入仓库或启动参数。本人可撤销自己的令牌；管理员可从「组织令牌」撤销本组织的令牌，不可查看原密钥。详见 ADR 0004。不通过直接改库为真实用户授权。

本地已有开发库可用 `.\scripts\dev.ps1 migrate` 升级，不重建卷。`.\scripts\dev.ps1 outbox` 处理一批到期项目事件并记录本地消费回执；`.\scripts\dev.ps1 dead-letters` 查询死信标识和错误码，不输出业务载荷。租约 30 秒，失败指数退避，最多 5 次尝试。没有安装后台计划任务；本地事件回执不代表已向用户发送通知或完成任何审批。

数据库与私有附件需作为一个恢复点备份。开发命令、隔离演练和每日保留要求见 [联合备份与恢复手册](docs/ops/backup-and-recovery.md)。

独立部署测试库时，按 [数据库运行账号隔离](docs/ops/database-roles.md) 分开迁移、API 与 Outbox 登录。此流程不会切换现有本机预览的连接账号。
