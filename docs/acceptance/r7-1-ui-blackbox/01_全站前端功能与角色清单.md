# 前端入口、角色与业务阶段

登录后的台账可按项目名称进入详情。首页展示账号与授权列表，项目名和新建入口可自行发现。项目阶段显示在详情标题旁。普通人员在多数页面只读到内部账号或人员编号，首页没有充分说明当前组织、健康采样不可见及下一环节的责任人。

## 入口口径

2个认证入口，9个普通全局入口，3个组织管理入口，19个项目入口，合计33个导航或条件入口。评审工作台、报告分析、凭证选择等为下一级交互，单独收录在控件索引。目录来源为当前分支的 `web/src/navigation.ts`、`App.vue`、各组件模板及首轮自然探索。控件数包含下拉选项、字段、表格扩展、条件按钮与抽屉，一个控件不会自动成为一次成功场景。

审查按16类职责建表，包括访客、组织成员、管理员、任命官、项目发起人、项目经理、出资人、独立评审、客户代表、财务核验人、独立对账人、风险接收人、变更审批人、委托签发人、政策登记责任人、隔离送达收件人。一个登录账户可具有多个职责。管理员没有替代财务或评审签署。本次出现的独立用户名可核对操作索引。

阶段覆盖清单为草稿、立项评审、立项否决、方案细化、可落地性评审、执行、暂停、交付、结项评审、已结项、复盘、终止及归档。新项目实际推进到立项评审。执行与归档的原有项目提供只读核对，适用后续写操作的缺口逐项列入矩阵。

## 可发现性

- 首页、项目名称、里程碑和需求的新建、四种助理模式可通过导航发现。
- 已核验凭证通过成本行展开查编号，再到附件页输入，业务链可完成但缺少同页选择。
- 风险接收由评审完成指派后另行交付请求编号。接收者的工作台不能自行列出该请求。
- 客户绑定、财务与变更独立资格属于受控登记。组织接入文档写明责任边界，普通业务页面没有登记入口。
- 审核条件待签、模型关闭、真实渠道收件、备份和外部Host等必须保留原始要求。

附件控件索引给出当前模板位置、事件与条件。可用证据与未测条件以02号矩阵为准。
