# 组织开户与项目接入

## 从邀请到项目

1. 已迁移的空库由运维初始化首位管理员。已有组织由当前管理员进入「组织管理 → 组织人员 → 邀请」，签发一次性邀请码，并在批准的渠道交给收件人。收件人在登录页「接受组织邀请」自行设置口令，再登录。职务提示用于组织资料，项目访问及审批权限各自办理。
2. 发起人在「项目台账」创建草稿，然后进入「人员任命」。通过页面独立的可提名项目列表选择草稿，按姓名查找同组织的可用人员，或使用明确的人员 ID。草稿发起人按原流程提名空缺的项目经理和 Sponsor，也可以提名普通成员、评审人或客户代表。现任项目经理和 Sponsor 可以在允许的工作阶段为已有项目提名后三类角色。
3. 有该角色任命权的另一人打开「待我发出的邀请」。发出邀请时须与发起人和被提名人独立。被提名人在「我的邀请」接受后，可点「打开已任命项目」，或从其授权项目台账进入。项目经理、Sponsor 和独立评审人的任命完成后，首关口仍按原材料要求预检。
4. 有当前项目访问权和相应任命权的独立人员，可以在「项目成员」撤销普通成员、评审人或客户代表。撤销处理按最新项目版本提交，保存理由和授权记录。评审中已有材料按旧流程重验。现任项目经理和 Sponsor 的替换继续遵循独立业务口径。
5. 客户代表接受项目任命后，具权登记人需将已核实的客户联系人绑定到代表本人。独立财务和变更审批另外办理资格与项目授权。上线前继续按真实试点验收单签核并发布正式规则。

## 受控终端登记

应用运行账号和工作台管理员界面没有受控登记写权限。具备专用迁移连接的登记人必须先核验组织、人员、授权依据和作用范围，再使用受保护的交互终端。通过 `PMO_MIGRATION_DATABASE_URL` 注入选定环境的迁移连接。授权引用填写可追踪的组织记录编号。命令输出审计请求编号。

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py -m pmo.appointment_authority_admin grant-appointment --org-id '<组织 UUID>' --operator-id '<管理员人员 UUID>' --person-id '<获授权人员 UUID>' --role reviewer --reference '<已批准的授权编号>' --expires-at '2027-01-01T00:00:00+08:00'
```

- `grant-appointment` 支持 `pm`、`sponsor`、`member`、`reviewer` 和 `client_representative`。撤销任命权使用 `revoke-appointment` 和相同组织、人员及角色，并填写撤销依据。续发生成新授权标识，旧邀请不会随之恢复。
- `bind-customer` 指定 `--project-id`、`--stakeholder-id` 及已接受项目任命的客户代表。联系人必须属于该项目且为客户类型。已有有效代表时先按业务规定结束其任命。
- `grant-finance-verifier` 登记组织核验资格。`grant-cost-reconciliation` 另外指定项目和有效期，只接受满足现有独立性要求的项目成员。`grant-change-approval` 指定项目、有效期和一类 `--target-type`，并核对该项目的评审人或 Sponsor 角色。登记人与审批人各自留痕。
- 普通账号丢失口令时，授权人员在同样的受保护终端运行 `python -m pmo.onboarding_admin --org-id '<组织 UUID>' --operator-account-id '<管理员账号 UUID>' --target-account-id '<目标账号 UUID>'`。两次隐藏输入新口令，成功后撤销该账号的旧会话和委托令牌，保留现有角色。

已建立的签核、分权、业务政策门禁及归档规则见 [真实试点验收单](business-pilot-acceptance.md)。合成环境的角色和凭证按 [隔离试点手册](synthetic-pilots.md) 使用。
