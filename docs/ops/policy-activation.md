# PMO 业务政策签核与激活

当前交付为待签候选。项目和组织内的草稿、材料准备及历史查询继续按各自权限工作。正式动作读取所在环境、组织和项目范围内生效的政策版本。R5 原文快通候选经齐备的独立评分后，由发起人确认并生成正式裁决与备案。启用需 DEC-04／19／20 明确批准 `review.charter-fast`，并满足相应的正式立项策略。原加强流程保留在旧策略及历史记录中，其正式替代口径由组织治理及评审制度负责人签认。

## 签核原件

部署工程负责人先固定候选制品和环境标识。API 与受保护登记终端使用相同的 `PMO_POLICY_ENVIRONMENT`，每个独立部署使用自己的标识。留空时正式策略保持待签。

使用拟签动作生成只读草稿并交对应负责人审阅。命令可多次指定 `--action`。

```powershell
python -m pmo.policy_admin draft DEC-09 --action requirement.exception
python -m pmo.policy_admin draft-all
```

每个政策版本的签署原件列明决议编号、版本、适用组织和项目、环境、动作、草稿中的政策内容及摘要、签署人及其授权依据、签署时间、生效区间。长期有效条款在原件中明确注明。存在多位必需签署人的条款，保存所有签字及资格依据后，由登记记录中的责任签署人与独立核验人绑定整份原件。

批准索引 JSON 使用以下字段。时间带时区，组织级范围的 `projectId` 为 `null`。仅已签署长期有效的条款允许 `effectiveUntil` 为 `null`。索引、签署原件和资格原件按组织私密资料流程保存。

| 字段 | 值 |
| --- | --- |
| `orgId`, `projectId`, `environment` | 原件中的部署范围 |
| `decisionCode`, `version`, `actions` | 签署条款和动作 |
| `policyHash` | 草稿输出的 SHA-256 |
| `evidenceRef`, `evidenceHash` | 受保护资料库的不可变原件版本引用和原始文件 SHA-256 |
| `approverId`, `approvedAt` | 责任签署人的 person ID 和实际签署时点 |
| `effectiveFrom`, `effectiveUntil` | 已签署的生效和结束时点 |

## 受控登记

数据库所有者连接 `PMO_MIGRATION_DATABASE_URL` 只在受保护终端配置。操作员用自己的 PMO 账号口令完成身份核验，口令在终端隐藏输入。调用命令前持有相应正式授权原件，使用内部定位引用或脱敏编号。

1. 具备管理员资格的独立登记人员使用 `grant-authority` 登记三类明示授权。签署与核验能力分别使用 `--capability approve` 和 `--capability verify`，条款编号填 `--scope`。激活能力使用 `--capability activate`，部署环境标识填 `--scope`。用 `--valid-from` 和 `--expires` 填写资格原件标明的实际有效期。变更人员资格用 `revoke-authority` 追加撤销回执。
2. 独立核验人对照原件检查批准索引中的每一项、确认签字及其权限和范围后，调用 `register-approval --statement <索引文件> --verifier <核验人ID> --original <签核原件>`。系统会核验索引、条款及原件摘要，成功后输出批准版本的 ID。
3. 持有当前环境激活能力且独立于责任签署人的操作员在有效期内调用 `activate --org <组织ID> --policy <批准版本ID> --operator <激活人ID> --reference <授权复核引用> --original <签核原件>`。激活将重新核验准确原件摘要、执行包和签署资格。后续试点人员仍按正常项目角色、委托范围与独立性规则执行。
4. 生效条件变化、原件撤销或替换时，保管人先通知激活责任人逐个撤销绑定该原件的版本。激活责任人调用 `revoke --org <组织ID> --policy <批准版本ID> --operator <激活人ID> --reference <撤销原件引用>`。替代政策新增版本并执行同样的核验与激活流程。历史版本仍保留当时的原件摘要。已生效政策的签署资格后续变化以正式撤销记录为准。

运行绑定表按请求可联查审计、版本和签署原件摘要。审批快照遇到政策版本变化，评审撤回重送、过期变更拒绝后重送、阶段审批重新提出。历史裁决和已使用的版本继续按原请求回读。策略撤销与正式并发写使用同一组织事务锁。

## 放行证据

待签草稿与隔离数据库中的合成测试记录分别保存。只有持有效政策和真实项目权限的人员，在授权真实试点中完成动作、回读审计并验证失效拒绝后，才计入正式政策验收。测试模式生成的版本携带合成标记。API 和 Outbox 无权登记、激活、替换或撤销政策。
