# 目标环境验收与停止线

本机回环 Compose、CI 和真实目标环境是三组不同证据。环境未知时不启动面向外部的服务、不开生产开关、不执行真实资料迁移。运维提供经批准的目标地址、维护窗口、连接和证据存储方式后按下表执行；业务放行另见[真实验收单](business-pilot-acceptance.md)。

| 阶段 | 责任和操作 | 可验收证据 / 不通过处置 |
|---|---|---|
| 制品与远端 CI | 工程发布负责人对照候选源码 SHA/树、锁文件与制品摘要；从 `dev/pmo-v1` 精确 SHA 触发既有工作流，仅认该 SHA 的结论；记录目标 Web/API 及基础镜像仓库摘要 | 提交、候选与文档证据区分。未完成、无凭据或不同 SHA 不算通过；本机镜像 ID 不是目标 registry digest。 |
| 环境和秘密 | 运维确认 Python/容器运行时、PostgreSQL 16、卷及容量、TLS/可信代理、数据库不暴露、私有原件 ACL、客户端和任务时区；模型默认关闭；证据和备份不在 Web 根目录 | 检查真实入口、访问边界、日志无凭据/私有负载、就绪探针和可达性。涉及对外服务或模型另行批准。助理和报告模型各自需要配置批准的项目 UUID 清单，清单缺失、为空或非法时停在人工流程。 |
| 联合备份与升级 | 停写并停止可能改库的 worker，按[联合备份](backup-and-recovery.md)验证数据库与附件同一恢复点。先在隔离副本核对数据与审批准则，再由 `pmo_migrate` 运行 `alembic upgrade head` 并应用[角色白名单](database-roles.md)。同候选 API、scheduler、Outbox 一起切换 | 源/目标迁移版本、原件摘要、旧回执及历史、归档读和禁止写。任何迁移失败保持停写；未迁移且无新写才可切回适配旧版，已提交新写则保全差异、在新库与附件卷联合恢复并重放/对账后再切换，不强制 downgrade 或覆盖原库。 |
| 角色与中断 | 分开迁移、API、Outbox 和备份账号；切换前后核对有效登录与禁止操作。用经批准的隔离测试栈短暂停 DB；恢复后查询同一项目、原件和回执 | API/worker 不是所有者；Outbox 不具业务表写权，API 不具角色/DDL权限，Web 不可直接读原件。记录 `live=200/ready=503`、恢复 `200/200` 和无重复消费；不拿其他使用中的库做故障演练。 |
| 周期任务和告警 | 运维配置每日联合备份、每日缺点告警、至少近 7 个成功备份日、每周隔离恢复；记录目标 RPO/RTO 及责任。分别注入持续未就绪、规则异常、Outbox 死信和备份失败 | 收到告警的人、渠道、时点、隔离恢复演练、版本/对象清单与真实耗时齐全。进程存活、目录存在或 `result=verified` 不能单独证明全链路。 |
| 外部通知 | 业务与运维选定目标通道和收件人范围，在获准环境核对事件→Outbox→通道→实际收件；重试/去重，错收件人不应收到 | 本地 inbox 只是投递回执，不是邮件/消息送达。通道未配置或未实收时单列，保留脱敏消息编号及人工核对。 |
| 性能与失败恢复 | 记录目标硬件、数据规模、浏览器、冷/热缓存、采样、并发、网络和错误率。先按规格 §9.1 的约 15 项目筛选及详情 `p95 ≤ 1 s` 目标测量；另量关键台账、worker 和故障恢复，预先约定目标负载 | 记录 p50/p95、样本数及错误率；判定不套用本机 p95。保存回滚指令与复查人，超过约定指标或恢复目标则保持 NO-GO。 |

解除条件：运维提供目标与权限并执行签核；工程负责人核对固定制品与对应 CI；业务负责人核准数据、账号和真实流程。密码/令牌不进入日志、截图或 Git；验收表只保留时间、环境标识、制品、状态和受控证据引用。
