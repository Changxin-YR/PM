**签核方式**：将经授权业务负责人的身份、日期、决定（接受默认 / 修改为其他规则）、原条款、变更理由、影响的 YAML 键、回归测试编号写入 `docs/adr/ADR-XXXX.md`，并更新受影响 `ruleVersion`。本文不代替实际签核。

## C. 开发实施路径：无需等所有签核才能动手

- **立即可开发：** M0，M1 的登录、本人草稿、项目列表、立项卡草稿、需求/里程碑/风险/预算草稿、基础数据库、权限、审计、幂等与 API/MCP 工具输入契约。
- **可在隔离开发环境实现：** M2～M4 的确定性规则函数、使用默认值的模拟项目、所有自动化测试；输出必须标记 `POLICY_PENDING` 而不是 `BUSINESS_APPROVED`。
- **不得以默认值替代正式授权：** 真正立项最终裁决、客户确认、范围变更、条件结项、正式成本核验和真实项目归档；在相应业务决策未签核时其管理正式验收为 `BLOCKED`。

## D. 新增工程决定（不是原文已有要求）

| 编号 | 工程默认 | 原因 | 变更影响 |
|---|---|---|---|
| ENG-01 | Web + REST + MCP(stdio) 共享 FastAPI 应用服务 | 避免人机规则分叉 | M0 开始不可另写第二套业务规则 |
| ENG-02 | PostgreSQL、SQLAlchemy/Alembic、Vue 3/TS、Pydantic | 实现路径清楚 | 如要更换，必须在 M0 形成 ADR |

| ENG-04 | 身份授权基于真实账号、独立 Agent token 和项目 DataScope；禁止 Agent 最终裁决 | 防 MCP 越权 | 不仅工具层，REST 层同样拦截 |
| ENG-05 | 任命 Sponsor/PM 需要有权人邀请与本人接受 | 防代理任命和权限自增 | 属独立系统权限落地补充，不改变原始 PMO 角色 |
| ENG-06 | 成功写事务与审计原子提交；被拒绝业务事务回滚后安全记录独立 denied 审计 | 防假成功、假安全日志 | 错误记录必须有独立事务和可见告警 |
| ENG-07 | MCP SDK 兼容候选 `mcp==2.3.0`；锁版本并按目标 Host 实测后决定使用 | 2026-11-19 官方 v2 稳定路线；不同 Host 仍需联调 | M0 不能宣称 DSH/Codex 已通过 |

**原则**：没有业务签核不应阻止全部研发，但不能把“可开发”误写成“可直接上线”。

## E. V1.0.4 工程自治权限边界（不等于业务签核）
- 业务未决仍是 DEC-04/07/09/16/18/19/20/26，**全部保持未签核状态**，不得因为系统默认值和 102 组参考向量通过就声称已获业务批准。
- Codex 可在隔离环境实现全部 M0～M4 模块并完成合成 E2E；缺外部签核项标 `BLOCKED_EXTERNAL`，只阻断正式终裁/真实项目上线，不阻断无争议代码编写和独立测试。
- `SYSTEM_ADMIN` 不是 Sponsor/Reviewer/Finance 的超级授权身份。所有人工审核由具备具体项目/能力授权的真实自然人完成。
- 对业务规则的更改须新增 ADR、规则版本和对应回归，不允许使用“实现方便”覆盖原始 Lite。
