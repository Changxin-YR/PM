# PMO V1.0.4｜Codex 自主修复权限边界

| 类别 | 可以自行决定 | 必须记录的证据 | 禁止操作或停止边界 |
|---|---|---|---|
| 代码组织 | 分层、文件命名、接口拆分、模块重构 | 设计 ADR + 受影响测试 | 不许另建一套 MCP 独立业务规则 |
| 依赖版本 | 在相容 SDK 主线锁定精确版本、修安全依赖 | lockfile + 实测日志 | 未联调不准宣称 Codex/DSH Host 兼容 |
| DB 迁移 | 新表、索引、字段、无损迁移、可回滚修正 | Alembic Up/Down + PostgreSQL 测试 | 未批准真实数据删表/清空/破坏性迁移 |
| API/MCP | 补DTO、修参数序列化、统一错误码、强约束输入 | OpenAPI 差异 + Schema 校验 + 实际调用 | 不可放通任意 SQL、直接 set_stage、自动裁决 |
| 权限 | 修组织/项目范围、授权过期、鉴权失败 | 越权正反测试 + 拒绝审计 | 不可让 Agent 通过 REST 绕过人类审批 |
| 幂等/并发 | 修事务锁、响应重放、409、重试退避 | 并发测试和净额核对 | 不可自动覆盖冲突版本 |
| 证据与报告 | Schema 验证、清洗/隔离、重试和人工澄清 | 证据来源链 + 模型失败测试 | 不可用模型输出代替核验凭证 |
| 前端交互 | 导航、表格、响应式、空态、无障碍和样式 | Playwright + 评审截屏 | 不得隐藏必需业务流程或把按钮可见性当鉴权 |
| 性能/运维 | 索引、备份脚本、Outbox、调度去重 | 故障注入/恢复日志 | 不准用多服务/新平台替代 Lite 的简单边界 |
| 业务规则 | 按原文/YAML实现既定算法和边界 | 单元测试+规则快照 | **不得擅改三Gate、八LR、分数线、审批权、条件结项范围** |
| 业务未签核 | 用合成数据+Feature Flag 编码，继续独立模块 | `blockers.md`、`POLICY_PENDING` 标识 | 不得把默认决议当正式签核，不得生产自动放行 |
| 外部连接 | 测目标 Host、模型、备份恢复 | 命令/退出码/脱敏日志 | 没环境就 BLOCKED，不能伪造通过，也不得上传客户数据 |

**推荐工作循环**：复现问题 → 识别业务/工程性质 → 自主选择允许的最小修复 → 更新契约和代码 → 自动测试与变异/权限回归 → 生成阶段证据 → Git 提交 → 推进未受阻的后续任务。工程问题可以自行迭代；所有真实审批/财务/客户签署和生产危险操作都不在此授权中。
