# PMO V1.0.4｜从原文推导的最小端到端验收样例

> 以下都是合成测试数据，不是真实试点。应转换为真实 pytest / PostgreSQL / REST / Web / MCP 测试，而非直接把表格样本数量当通过结果。

| 样例 | 输入或动作 | 确定性期待结果 |
|---|---|---|
| A01 立项高分 | 四维全部5分，已任命 Sponsor/PM，有完整 Charter | 权重总分5.0，满足快速立项**建议**；Sponsor 确认和合法 Decision 仍不能跳过 |
| A02 立项临界 | 四维全部4分 | 总分4.0，落在 `3.2≤S<4.2`，属于普通通过建议区间；全为4分时按当前默认低分阈值不生成弱项整改任务，仍保留决策记录 |
| A03 立项一票否决 | 任一生效评审人的某维=1，而平均总分>3.2 | 阻止直接通过；复议一次，保留前后评分历史 |
| A04 落地短板 | 五维分数 `[5,5,2,5,5]` | 任一维≤2，不能进入 executing，创建补强任务且幂等 |
| A05 费用临界 | 预算100、已核验实际70、剩余预测50 | 预测120，偏差`0.20`，成本红；`>0.15`预警，**不满足严格 >0.20 的再评估触发条件** |
| A06 凭证冲销 | +100 verified，-100 verified，+70 verified | 权威实际70；原始正向凭证保留，不得二次抵扣 |
| A07 需求例外不跨越成本 | 一项P0缺客户确认，合法书面偏差接受，但金额偏差25% | 即便需求例外有效，LR-07仍拒绝结项 |
| A08 阻塞风险例外不可滥用 | 需求满足100%、金额/人天正常，但关键风险阻塞未关闭亦无移交确认 | LR-07拒绝结项，产生缺口清单 |
| A09 两期缺周报 | executing项目，连续两个到期周报周期无提交 | `untrusted`，暂停本次正式三线发布并保留旧快照仅供历史参考 |
| A10 黄线合成 | 时间黄、成本绿、质量绿，无红 | 按**原文特殊规则**总体绿，但显示时间黄线细节 |
| A11 Agent越权 | Agent token只授权项目X，直接 HTTP 查询项目Y及其附件 | 403/404受控拒绝，无数据泄露，安全审计记录 |
| A12 MCP新项目草稿 | token具组织级创建授权，成功创建drafting并修改本人草稿 | 同令牌仅可管理这个新建草稿，不获Sponsor/PM/Reviewer，也不可访问其他项目 |
| A13 幂等重放 | 相同actor/operation/key/payload重复提交 | 一次写入；返回首次稳定ID/状态/响应，不能仅返回响应hash |
| A14 Gate事务失败 | Reviewer终裁过程中注入审计/状态更新异常 | Decision、状态、成功审计、Outbox全部回滚，不出现半通过 |
| A15 模型关闭 | 不配置LLM密钥，尝试正常Web立项、需求、成本、结项 | 人类功能可用；AI面板明确未配置，不能伪造结果 |
| A16 终止复盘 | 人工终止并合法进入retrospective | 终止复盘路径成立，但不得伪称已通过正常结项门槛 |

这16个样例为补充验收入口，不取代原文Q1～Q8、第三方真实客户端T01～T10、2026-11-19版本的参考向量102组。不能直接当成产品已运行的证据。
