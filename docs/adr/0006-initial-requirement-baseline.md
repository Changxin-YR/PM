# 0006：初始需求基线共同确认

规格 §5 要求送方案评审前 PM 和有权客户代表共同确认；`human_customer_confirm` 是交付验收，不用于初始基线。新增人工查询与签署两个工程接口，不计入 95 个基线操作，不注册 MCP。Agent 即使直接调用 REST 并具有同名动作也被拒绝。

以项目下全部未取消需求（含 ID、版本、描述、优先级、验收标准及计划确认日）的有序快照为确认对象。项目锁串行化草稿写入与确认。当前有效 PM 首先确认；不同的、已接受本项目 `client_representative` 任命且关联本项目客户 Stakeholder 的有效会话方可终签，终签时再次检查 PM 资格及快照。普通联系台账登记不建立认证关联或项目资格。本地测试身份由独立测试 schema 建立；不会赋予实际用户客户代表身份。

签署记录、确认理由、原版本快照不可变。任一内容或行版本变化都要求重新确认。终签、全部需求升至初始 V1、幂等回执、审计和 Outbox 同事务。初始基线签署不是交付、验收或书面例外；不改变需求交付状态。后续基线变化必须另行审批。
