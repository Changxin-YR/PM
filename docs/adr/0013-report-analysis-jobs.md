# 0013 报告分析与人工接管

依据：V1.0.4 §6、§8.5–8.6、T06。组织权限、可信阈值及政策签核状态不变。

- 已实名提交的报告由仍有权限的作者或本项目 PM 请求分析。`If-Match` 绑定 `report.revision`，服务重新计算正文哈希；数据库收据冻结来源和请求人的会话 UUID。相同主体的同键请求重放首次响应；同一报告只有一条活动作业。正常请求可复用当前版本已有结果；`forceNewRun=true` 只在当前没有活动作业时建立新收据。发布会改变报告 revision，异步作业不会将旧输出落入新版本。
- 单独的进程领取 40 秒租约。网络调用不持数据库锁；提交前重新按会话、组织、项目角色、报告 revision/hash 和租约核验。改版、退出、失权、归档时作业以 `stale` 结束，不写建议。最多预留两次执行机会；无效 Schema/出处可以再尝试一次，超时、不可用不自动重复请求。失效租约可补跑，耗尽时转人工；旧租约不能写入。未提交的终态、任务、审计及 Outbox 一起回滚。
- 仅显式开启才可能调用模型网关。网关请求含固定 `process_manager` 模式、独立指令、封闭候选 Schema 和有限的原话文本，不发送报告结构数值、资源 ID、附件字节或人/Agent 的认证凭据。报告文字仍可能含人工填入的敏感内容，真实外发由部署方单独审批。网关没有工具/数据库权限；不跟随重定向，不使用环境代理。模型应答的值和原话必须实际出现在发送文本中；源引用、路径和偏移由服务生成。
- 建议保存在分析收据，绝不自动进入 Fact 表。人工选用时先预填，明确保存后仍由正式候选服务核对该版本的原话和权限；矛盾经同一 Fact 服务生成 PM 澄清，待实际核验后的事实才可用。未审核的模型输出不能降低已核验事实的信任、执行操作或生成权威指标。尚未集成自动周报发布链路。
- 模型关闭时请求直接形成有原因的人工处理收据，无需 worker；模型失败时产生同源去重的人工任务。原始报告、人工提报和 PM 发布不依赖模型结果。终态收据不可覆盖或删除；不允许降级丢失历史。
