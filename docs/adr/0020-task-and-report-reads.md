# ADR 0020｜任务与报告读取契约

依据 V1.0.4 §6.1、§7.1、§8.4、§20.6 和工程 DTO §6–7。冻结规格、业务规则及接口和工具数量不变。

- `pmo_task_list` 和 `pmo_report_list` 的运行 MCP Schema 增加可选 `page`、`pageSize`，报告另允许 `reportType=daily|weekly`。默认仍为第 1 页、每页 20 条，上限 100。适配器原样传给已有 REST 查询，不单独读取数据库或改变权限。越过末页返回同一授权范围的 `total` 和空 `items`，不把超大页偏移交给数据库。
- 列表的排序和过滤均由 REST 服务在 SQL 中完成；先限真实项目、授权关联和资源范围，再计数、分页。`sourceRefs` 只包含返回页里的稳定资源版本。不同请求的 `asOf` 是各自查询时点。
- §6.1 的「本人相关」按已记录作者判定：普通成员仅可读本人报告；现任 PM、Sponsor、Reviewer 和已任命客户代表可读其项目内已提交或已确认的报告。发布不向普通成员自动扩大范围；草稿仅作者和现任 PM 的人工会话可读，Agent 还需显式项目及动作授权。
- 报告列表、详情、Fact 与报告关联附件执行同一资源范围。附件读取校验真实 `project_id` 和 `report_id`，无权时不返回元数据、原件或该报告的计数；不重写旧链接、文件或已签回执。`collectionRevision` 仍是项目附件集合的并发控制版本，不是可见条数。其他附件、核验人、实际字节和 SHA-256 校验不变。
- 时点消费按同一项目、类型和周期，在该时点前已提交且已确认的回执中选择最高版本，不使用查询时的发布指针回填历史。读取同时核对原内容哈希；旧确认标记无真实确认回执时，不当成有效发布。Web 与 MCP 列表、详情均区分当前发布和历史版本，MCP 不返回私有草稿指针；写入重放保持原回执。
- 归档后报告作者和现任 PM 仍可分页读已有分析记录；是否能读历史与是否能启动分析或提报候选分别判断。只读授权不恢复任何归档写入。
