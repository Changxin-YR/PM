# 0019 项目阶段的正式授权

状态：工程实现，不替代业务签核。依据：主方案 §4.1、§20.4–20.5 与 LR-01。

- Sponsor 保持其现有权限和独立性要求。另一名人工审批者须同时拥有有效账户、同组织的有效项目参与任命，以及一条尚在生效且未撤销的组织授权记录。授权只对同一项目、人员及一条 `from_stage→to_stage` 有效。它不赋予项目可见性、Reviewer、Sponsor 或发起权，也不沿 Agent Token 传递。一般管理员身份或变更、财务授权都不能替代阶段授权。
- `0032` 新表初始为空，无人因此获得新权限。`source_ref` 是已由组织认可的、不含私密信息的决议或登记编号，原件由组织按既有流程核验保管；页面输入附件编号或勾选状态不会签发授权。仅由组织确认的带外登记人按[运维手册](../ops/database-roles.md)登记或撤销。API 账号只读及加锁，Outbox 账号不可读写。撤销仅能追加一次时间及来源，不可还原或覆写；更新授权需新记录。
- 终裁锁定项目与审批者的有效授权、参与任命；重检查现有申请和所需发起人确认。最终阶段迁移仍由 `transition_project()` 完成。Decision、绑定人的权限来源及哈希快照、阶段、审计、Outbox 和幂等回执同事务提交。以后撤销不会改写已经发生的 Decision；页面继续显示其当时授权来源。没有新增 REST 或 MCP 操作。`POLICY_PENDING` 不变。
