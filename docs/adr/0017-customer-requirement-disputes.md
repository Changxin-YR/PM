# ADR 0017：绑定需求版本的正式客户争议

依据：主方案 §5.3–5.4、§5.6 LR-07，规则 `quality_line.confirmed_dispute_is_red`。项目联系人或争议 Fact 本身不构成正式客户陈述。

- 客户在现有工作台展开需求后，可针对当前有效、已冻结版本提交争议。服务端从人工会话取得身份，核验同组织、项目内有效客户角色与已绑定的 `customer` 联系人；内部评审、PM、Sponsor、发起人、需求作者和内部验收人不能代填。绑定与签核的真实授权未放行，写入沿用隔离合成 schema 保护。
- `0028` 回执记录客户、成员指派、客户联系人、需求记录 revision、基线版本、陈述、时间及审计请求号。该认证陈述即争议来源；不把上传附件、客户昵称或模型候选解释为客户声明。只有原陈述人持相同有效客户授权可撤回一次，原因和时间另存，不能更改原文。
- 同一客户对同一需求基线同时只能有一条未撤回陈述。后续经正式 `ChangeEntry` 生效的新基线仍须独立交付与签收，旧基线争议保留为历史，不作为新基线的陈述。撤销角色不会抹去已收到的争议。
- 当前有效争议使质量线红灯，并暂停本条需求计入已确认权重，不删除原确认。它仍是结项复核的独立缺口，不能用早先签收或未列明本争议的书面偏差回执覆盖。送审后发现新争议须撤回重送，即使之后又撤回争议，相关基线上的回执也会改变快照。
- 工程接口：`GET/POST /api/v1/requirements/{requirementId}/disputes`、`POST /api/v1/requirements/{requirementId}/disputes/{disputeId}/withdraw`。状态变更使用既定幂等键；打开按需求 revision，撤回按争议 revision，统一在项目锁内检查。业务、成功审计、扫描待办和 Outbox 一次提交。历史只对具备项目读取权限的人工显示，无 MCP 写入。

没有新增审批层级或修改 DEC-07/09 的签核状态。
