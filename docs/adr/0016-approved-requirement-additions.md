# ADR 0016：新增需求复用冻结基线变更

来源：主方案 §5.3–5.4、§5.6 LR-05、§6.2、Q8/T05/T07。无需新增业务角色、许可或表。

现任人工 PM 在共同签署冻结后可提出新增需求。申请为既有 `ChangeEntry` 和 `baseline_change` 审批意向，不写 `requirements`，只预留资源 ID。申请指纹绑定初始签署 revision/hash、新条目和原因。未批准条目不进入需求清单、初始/有效分母和正式进展；LR-05 证据引用原冻结基线与变更意向，而不是尚不存在的需求。

批准复用项目锁、既有 DEC-07 隔离政策、独立审批授权、版本及 payload/snapshot hash。成功在同事务创建需求第一版、记录前（未存在）后状态、关闭 LR-05、写审计与 Outbox。拒绝仅保留历史。没有真实政策证据不得正式批准，Agent 不得调用人工终裁。申请和批准的工程新增入口不改变既有 40 个工具契约。

有效范围从客户共同签字的初始清单和获批记录还原。新增计入 `approvedChangeCount` 与有效需求权重，不计入 `initialCount` 或初始需求变更率分子。新增第一版仍使用批准时点以后的独立证据走交付、验收及客户确认；不得借新增时的裁决充当客户确认。后续修改/取消沿用 ChangeEntry 历史。
