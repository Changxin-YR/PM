# 0021 工作台投影与健康时点

状态：开发采纳。依据主方案 §2 UI-01～03、§7；不改变规则版本、业务授权或冻结的 95 / 40 目录。

`GET /api/v1/project-overview` 仅限人工会话。与 `pmo_project_list` 共用项目 DataScope 和 `filters[stage]` / `filters[keyword]`。在一个 SQL 读取中先应用权限、筛选并分页，只为该页查找同组织已接受且未撤销的 PM 任命与最近持久健康采样。只有基本项目访问权的发起人不获得这些材料。`canEditDraft` 与原草稿写服务共用发起人和阶段条件，写服务仍独立锁定、校验权限和版本。

`healthSample` 有采样时点、规则版本、发布状态和快照引用；它是历史采样，不是当前灯色。查询不遍历项目重算健康，也不因读取写快照。旧格式和未来样本不进入此投影。Web 给列表读取得出的时间和快照时间不同标签；当前健康仍走确定性服务，数据不可信时不得补用过去灯色。MCP 不新增此工具，也不接收 Web 专用字段。

人工详情 `GET /api/v1/project-overview/{projectId}` 锁定已授权项目，复用立项摘要和 `health.current`，仅返回当前四指标及所用时点，不能提交或发布健康记录。仅具基础访问权限的发起人只读项目基本信息。同项目最近五条已提交阶段流转按版本倒序，带实际回执、时点及版本；待审批申请不进入此列表。原阶段与评审台账继续提供完整历史和受控写入。

`GET /api/v1/me/strengthening-tasks` 只为当前人工会话返回仍有项目访问权、本人指派、非归档且未办结的纳管任务；不能从查询指定其他责任人。不按 PM 或管理员角色扩大本人队列。计数与页数据使用同一 SQL 快照，记录 `asOf`，按期限优先、无期限最后排列。项目台账的可选 `taskId` 仅在原权限和项目范围内缩小查询，用于定位跨页任务。事实澄清等受控任务不因进入待办而可直接修改；原任务写服务仍独立检查角色、版本、幂等和归档状态。未新增 MCP 工具。
