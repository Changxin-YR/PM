# ADR 0009：冻结基线的审批和生效

申请与 `approval_requests` 同事务保存。ID 对应同一变更，绑定申请人、实际委托人、当前资源完整快照摘要、业务负载摘要、申请版本及规则版本。迁移前的待审批记录没有这些凭据；不能事后补签批准。独立授权者可在隔离演练中拒绝旧申请，再由 PM 重新提交。

审批须同时满足有效的项目 reviewer 或项目所指定的 sponsor、同项目/同对象类型的未撤销且未过期授权及独立性。没有默认授权，也没有 HTTP 自授接口。DEC 未签核期间真实裁决仍被拒绝；只有显式绑定随机测试 schema 才可走成功路径。

批准、应用、不可变前后快照、理由、审计及幂等回执在同一事务。需求改版清除上一版交付/验收状态，保留旧状态及回执；重新交付须上传并核验当前版本生效后的附件。里程碑只更改获批字段并重新评估 LR-03；预算保留旧条目及流水外键，生成新的有效预算条目。初始共同签署的需求基线不覆写。拒绝不改变业务对象，旧版本或负载不匹配不能批准。

本 ADR 不代表获准真实裁决；当前尚未完成全部审批人配置界面、关口决策和综合健康计算。

## 运行契约：四类变更快照

依据 §2.1、§5.4、LR-05、Q8/T05 和工程 DTO 补充 §1、§5、§7。`change_contract.py` 向 REST 和 MCP 发布同一组按目标类型分支的字段约束。前后必须是同一组可更改字段；日期为本地日历日期，预算为十进制字符串，立项卡风险只接受 `statement`、`response`。需求取消是独立的状态分支，新增需求继续使用 [ADR 0016](0016-approved-requirement-additions.md) 的人工接口和初始基线回执，不可由通用申请伪造。服务在授权及幂等回读后校验新写入，再按实际资源与版本核对旧值；合法旧键响应和基线/审批指纹算法不改。

历史数据不重写。非现行字段结构的旧快照以 `legacySnapshot: true` 在授权人工界面保留原 JSON，不当作新申请或有效批准。MCP 需求历史保留这类记录的 ID、状态和来源，不透传不受控快照；两侧快照同时省略表示该情况。正常变更和获批新增的前后值继续可读。冻结的原始契约文件保持不变，运行约束在发现及 HTTP OpenAPI 中发布，无新增路由或权限。
