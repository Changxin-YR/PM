# ADR 0014：组织目录、一次性交付与账号停用

来源：主方案 §6.1、§20.4、T02/T04/T05/T07，OpenAPI 四个 `admin_users_list`、`admin_members_list`、`admin_user_invite`、`admin_user_update_status` 基线操作。

组织目录只对有当前 `system_admin` 授权的人工会话开放，按组织过滤。组织邀请通过独立的接受接口完成账号开户；`Person.role` 仅是职务提示，不授予 `user_roles`、项目角色或业务审批能力。项目成员任命继续走既有流程。管理员不能从普通账号启停接口停用自身或其他组织管理员。

邀请码只有签发成功的首个响应头交付一次，响应不得缓存；数据库只存摘要，不通过列表、回执或日志交付原码。重放返回原邀请元数据，不重新交付密钥；首个响应丢失应撤销再签。开发版由组织管理员通过获准的带外渠道交付，没有自动邮件投递；收件人验证依赖保护该一次性凭据，不能作为客户签收证据。接受接口不接受 Agent Bearer；未认证接收人持有效码自行设置密码，限时且限速。接受时重验签发人账号及组织管理资格。

停用按账号 `status_revision` 并发控制，同事务保存版本、审计与 Outbox，撤销既有浏览器会话及该委托人同组织的 Agent Token。启用只能重新登录及按授权重新签发，不复活旧凭据。组织消费者用 `organization_event_inbox` 去重，不制造项目 ID。部署时先迁移并应用数据库白名单，再统一切换 API 和 Outbox 版本；旧 Outbox worker 不认识组织事件，不应继续领取新事件。
