# ADR 0010：关口预检与送审

`gates/check` 与 `reviews/prepare` 使用同一个评估器；授权后的成功读取不写业务记录或生成决议。准备接口只返回缺口和出处，不返回内部材料快照或原始人员资料。Web 用准备响应的 `X-PMO-Can-Submit` 和 `X-PMO-Project-Revision` 显示操作及构造请求；它们只是提示，POST 会重新校验。评审列表固定返回最近最多 100 条和真实总数，与冻结列表输入保持一致。

`transition_project()` 是唯一项目阶段写入口，本批只实现三条送审边。先锁项目，校验对应动作和当前项目主体资格，再匹配已完成幂等回执；新申请继续检查版本、阶段、待审记录及最新材料。立项允许有效 Initiator 或指定且有效的 PM，落地与结项只允许指定且有效的 PM。四个工具均要求匹配的动作权限和显式项目委托，建草稿时自动取得的范围不够。离开草稿且无其他项目角色的 Initiator 可读本人项目摘要、立项关口及立项评审回执；不由此取得其他关口或材料的权限。已失效的授权不得重放。

迁移 `0016` 增加两张追加式表。提交保存待评审 Review、完整材料及哈希、当时有效且独立的 reviewer 名单与任命记录、前后阶段和版本、主体、请求关联、成功审计、幂等回执和 Outbox，全部同事务写入。名单作为快照的一部分，不把受邀人写成实际到会人员。独立评审人至少一名是当前预检默认值，不代表 DEC-04 已签。成功进入评审不等于通过该关口；评分、改轮、复议、终裁和其他阶段边不在本批。

落地要求 3 至 8 个有效里程碑、同一需求清单上两个独立人工签署及完整的当前基线、金额和人天预算草稿、带应对措施的风险登记。结项检查当前需求权重、P0 和人工作出的客户确认，复查关联证据、双口径绝对偏差、剩余预测和阻塞风险。逐笔凭证核验不证明总账已对账；独立对账记录尚无受控写入，故当前结项送审拒绝。也不接收自由文本或布尔值充当风险接收确认、零预算声明或书面例外。未签的政策、外部验收及生产放行均未通过。

## 0017：独立评分、复议与终裁

每张卡完整保留锚点、理由、冻结材料引用和实际附件核验快照；当前 Reviewer 指派须仍有效且在本次提交的冻结名单中。共享项目可见性、组织管理员身份和 Agent 委托都不能替代 Reviewer。复议留下前版原始卡，只用同一 Reviewer 实际重评的新卡取代其旧卡。阈值使用精确的分子与分母；快速立项额外绑定 Sponsor 和发起人对当前评分集合的两份人工确认。常规立项补强按维度与 PM 去重；无固定承诺期限的自动任务不虚填日期。落地有条件通过必须指定项目内有效人员与未来期限。LR-02 阻断先回滚并记 denied，再独立按维度和 PM 记整改，不变更评审状态。

送审写入审批请求，冻结相关资料，项目提交版本见阶段历史；当前性比较只包含决定所需业务资料，不以无关任务或项目技术时间戳判失效。决议事务锁定项目，核验申请主体、基线、附件字节与活跃授权后同时保存 Decision、评分和签认快照、正式基线、阶段、成功审计、幂等回执与 Outbox。首次批准立项锁定立项卡；落地批准由已冻结预算草稿生成可追溯的金额/人天基线。无剩余预测输入时保留计划预算作为初始保守估计，绝不自动清零。0016 已送审的旧轮次没有新的审批请求，不补造；有权申请方可撤回重送。`pmo_decision_get` 只读公开决议字段；人类工作台按权限读取理由及历史。真实终裁保留 `POLICY_PENDING`；相互独立的测试会话和合成 schema 不代表现场签核。

运行 OpenAPI 的评分写入和历史共用封闭的立项/落地维度模型。每维按既有证据规则至少有一条来源且不重复，OpenAPI 按分值声明五种锚点的对应关系；实际关口类型与指派仍由服务端验证。有效历史的字段、数据、关联及计算不变；不开放给 MCP。
